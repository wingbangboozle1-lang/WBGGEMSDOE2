# Project working agreement

At the start of a session read `README.md`, `research/findings.md`, `evidence/run_card.json`, and `docs/PROJECT_CHARTER.md`. Treat the preserved original prompt as historical context, not as evidence or perpetual authorization. Respect the active branch and current higher-priority instructions.

- No real competition slot without the separate selector; no copies disguised as novel predictions.
- Enforce the literal duplicate stop against **every** registry raster before placement and on final dots; an incomplete registry cannot prove uniqueness. The support of a registered continuous probability prior is ambiguous under the dot rule: seek clarification rather than silently exempting it.
- Use the assigned method lane and the unchanged pinned shared template; fix shared tools upstream, not in a private fork. Derive catalogue features from visible faults only for each spatial holdout, and run single-feature leakage canaries.
- Do not call a leaderboard projection or user claim an organizer receipt. Label observed leaderboard values, holdout scores, evaluators, positive counts and confidence intervals accurately. Do not silently repair candidate values.
- Keep data and large generated assets out of Git; document sources, rights, hashes, limitations, stale states and negative results.
- If evidence, data access or policy blocks completion, say so and fail closed instead of fabricating a candidate.
- **The shared hide-and-recover holdout cannot rank rasters built with the full catalogue** (measured Spearman −0.85 against owner-reported values; `evidence/holdout_calibration.json`). Use it only for within-lane comparisons where every arm is fold-local and catalogue-agnostic. Never quote a cross-family holdout number as evidence, and never quote the withdrawn 0.1321.
- Lane scripts that are live and safe to re-run: `build_feature_bank.py`, `lane_blind_propensity.py`, `emit_and_score.py`, `calibrate_holdout.py`, `emit_final_submission.py`, `audit_candidate_registry.py`, `build_lane_b_release.py`. The last one re-hashes the committed TIFF and refuses to publish the download button if any gate disagrees; `scripts/build_site.py` repeats that verification before rendering the dashboard banner. Do not hand-edit `docs/submit.html`, `docs/data/run-card-lane-b.json` or `evidence/run_card_lane_b.json` — regenerate them.
- `evidence/run_card.json` remains the canonical card for the two rejected parallel research lanes and stays negative. `evidence/run_card_lane_b.json` is the canonical card for lane WBG2-B. They describe different lanes; neither supersedes the other.
