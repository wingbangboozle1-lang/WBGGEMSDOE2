A PRACTICAL CHECKLIST

From evidence
to submission.

A single GeoTIFF is the deliverable. But a local format pass is not a prediction of performance, and a previously submitted file is not a new experiment.

1. Wait for the machine gates

Before a TIFF can be considered for a weekly slot, the project must check an immutable complete registry before placement and on final dots, run each feature's leakage canary, compare a buffered whole-segment holdout against the same-fold incumbent, and re-read the saved bytes against an authenticated organizer template. A paired confidence interval must support an improvement. The selector then checks the current quota. No human geological inspector is used by these technical checks.

2. Check the exact TIFF

The official format requires a single float32 band, EPSG:32611, the exact submission grid, and confidence values from 0 to 1. The portal also accepts a ZIP containing one GeoTIFF. The official problem description calls for null/NaN outside bounds; our optional strict whole-array finite check is a diagnostic, not a substitute for organizer guidance.

With an authenticated official template in place, the local command is:

python scripts/validate_tif.py candidate.tif --reference /path/to/official_template.tif

The report separates NaN, infinity, below-zero, above-one, and masked-cell counts inside and outside the reference footprint. To additionally flag any non-finite or out-of-range cell anywhere, add --strict-all-finite. The command does not clip or silently change values. A successful report says only “format valid against reference”; it never approves a slot or guarantees portal acceptance.

The previous “Predicted values must be in range [0, 1]” error cannot be diagnosed without the actual rejected bytes. A NaN, infinity, negative value, or value above one can each require investigation. Do not assume that a zero-filled exterior is necessarily accepted or compliant.

3. Submit only after approval

  1. Enroll and sign in to the GEMS Prize on DrivenData; review the current rules and the remaining weekly quota.
  2. Download the exact, newly approved .tif from the project. Check its SHA-256 against the run card. Do not use a historical or research-only file.
  3. On the competition page, select Submit → Make new submission. Choose the TIFF, or the single-TIFF ZIP if preferred.
  4. Copy the unique name and short note supplied with that approved artifact; the project limits the note to 140 characters. No name or note is provided for a non-existent candidate.
  5. Submit once and retain the organizer's receipt. A local holdout result is not that receipt. Select one final submission for both prize rounds before the deadline.

The official rules describe up to three automated-scoring submissions per week, subject to the platform's current limit. Finalists must deliver reproducible code and disclose the extent of generative-AI use in the narrative. The overview lists 3 December 2026 at 23:59 UTC, while rules Appendix A.1 separately mentions 5 p.m. ET for final content or the submission form. Whether these are different deliverables is unverified; plan for the earlier time and check organizer guidance.

Access limitations

The public owner mirror of the feature raster was restored and hash checked locally, but it has not been compared with an authenticated competition download. The mirrored sample differs from the organizer's described all-absence sample. Nineteen label-free raw bands were cached using the shared builder, but the derived feature bank, complete registry, private truth, receipt, account quota and organizer acceptance are unavailable.
