THE BLOCKER

Why the uniqueness gate cannot pass

The shared registry tool treats every finite positive pixel as support. One previously registered continuous GEMSDOE48 raster is positive on every pixel of the mirrored competition footprint.

Any nonempty candidate has every dot at distance zero from that support. Its overlap is therefore 100%, greater than the specified 70% limit. This is a rule conflict, not proof that all candidate geology is identical.

Excluding dense rasters would change the rule; this project does not silently do so. A separate discrete lattice also imposes an 82.34% minimum overlap at a 37,654-dot budget.

THE 0.2778 QUESTION

What H33 actually did

The H33 raster is exactly the D2.8 support after removing dots within two pixels of the mapped catalogue: 44,090 → 37,654 dots. The intermediate one-pixel prune has 40,199 dots. These are measured pixel relationships, not score explanations.

The metric favors recall and discounts predictions near new truth, so thinning may reduce redundant predictions. But known faults are masked only pixel-exactly, and newly mapped truth may lie close to them. Pruning can also remove useful predictions.

The original H33 audit marked the file UNSCORED and listed no receipt. The user's 0.2778 attribution could refer to a later upload, but we cannot verify it from available evidence. Whether a genuinely new submission beats it is unknown.

SUBMISSION GUIDE

How to submit—once a file is cleared

These steps are conditional. There is no cleared file to download today. Do not use a historical research link as a substitute.

01

Check the decision

Wait for a new, uniquely generated file with passed pre-placement and final-dot registry checks, feature canaries, and a paired holdout win. A separate selector must approve the slot.

02

Download & verify

Download the approved TIFF; confirm its SHA-256, single float32 band, reference CRS/shape/transform, and finite in-footprint values in [0,1]. Follow the official outside-bounds null/NaN rule and clarify the treatment of in-bounds uncovered cells.

03

Upload on DrivenData

Sign in to the competition, check available submissions, select the exact file, and enter its generated name and note (at most 140 characters).

04

Keep the receipt

Confirm portal acceptance and record the file hash, timestamp, and submission-page score receipt. Choose one final submission under the rules, including any required AI-use disclosure.

About the [0,1] error. Do not clip silently: reject NaN, infinity, nodata sentinels, or out-of-range values inside the footprint. The official page specifies null/NaN outside the data bounds but does not clearly define in-bounds uncovered cells. The shared writer uses zeros there; portal acceptance of either convention has not been verified here. Local validation is not portal acceptance.
