What this is

WBGGEMSDOE2 is a reproducible pipeline for the GEMS Prize Challenge (geological fault detection for geothermal resource mapping, DrivenData competition #306). It generates a unique submission TIF from hypothesis H1 — blind-conduit hydrothermal breach (geophysical-edge detection on cross-cutting structural trends, decayed with the competition's 300 m triangular kernel; not seeded from any USGS/INGENIOUS catalogue fault, so it can catch faults missing from the catalogue — the privately labeled test set). Full method: scripts/make_submission.py, rationale: hypotheses.md.

How to submit (no manual inspection needed)

  1. Sign in to DrivenData at the competition data page (login required to download sample_submission.tif, training_features.tif, labels.tif).
  2. Produce a single-band float32 GeoTIFF matching sample_submission.tif exactly: CRS EPSG:32611, 100 m, same bounds/geotransform, values in [0, 1], no NaN (write 0 outside the survey footprint).
  3. Validate locally before uploading — this catches the "Predicted values must be in range [0, 1]" error:
    python scripts/submission_writer.py --check your_file.tif --reference data/sample_submission.tif
  4. On the submission page, upload the .tif (or a .zip containing one .tif), enter a Note (≤ 140 chars, e.g. "clustering with k=25"), and submit.
  5. Pick the single submission to score across both prize rounds before the deadline.

Validation gate results (this build)

  • Format gate (CRS/shape/transform/float32, all cells finite in [0,1], zeros outside footprint): PASS — scripts/submission_writer.py re-reads the saved bytes and ground-truths them.
  • Lane-UNIQUENESS gate (parallel-run protocol §1): Spearman \|ρ\| ≤ 0.90 on the surface and ≤ 70% of dots within 3 px of any one registry raster — PASS against all 58 GEMSDOE32 registry rasters (max \|ρ\| = 0.0021; max 3-px overlap = 21.72%).
  • HOLDEOUT-DTI gate (hide/recover whole fault segments, α=0.2, β=0.8, 300 m triangular kernel, 95% spatial-block CI): BLOCKED — labels.tif is not available without a DrivenData login (scripts/download_competition_data.sh). A projection is never written as a score.
