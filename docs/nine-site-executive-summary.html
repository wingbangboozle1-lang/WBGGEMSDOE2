4. Why did GEMSDOE32 (0.2778) score highest? (PhD-level reading, labelled)

  1. It is the pruned member of one family. Its 37,654 dots are the 44,090-dot "D2.8" mask with the dots within 2 px of the mapped catalogue removed (repo lineage note, evidence/retired_20261027/why-b2-scored-2778.md.txt). I re-measured that it has 0.000 of its dots within 2 px of the catalogue. Every other site's dots are ≥ 86.7 % inside another site's halo, so the nine scores differ by budget and pruning, not by method.
  2. Mapped-fault pixels are not penalised. DrivenData staff state that known USGS/INGENIOUS fault pixels are masked from evaluation and do not count toward penalty terms (community reply, "Sep 16"). Dots on mapped faults therefore earn nothing and cost nothing; removing them frees budget for unmapped-fault candidates. This is an inference from the official rule, not a confirmed cause.
  3. Metric arithmetic. DTI = TP_w / (TP_w + 0.2·FP_w + 0.8·FN_w), with a 300 m triangular kernel (official metric). The repo's inversion (USER-REPORTED scores, F = mass assumed) implies about 12,783 scored truth pixels and about 41 % weighted coverage at 0.2778 (data_public/gemsdoe_metric_model.json). PROJECTION-level; the assumption F = mass is conservative and unverified.

5. Can we beat 0.2778? — honest answer: not demonstrated.

  • The only local tool that uses the official formula and the shared fold code ranks GEMSDOE32 below random dots (0.0067 vs 0.069). That is because it scores withheld mapped faults, which the official metric masks, so the local holdout measures the wrong target for this family. HOLDOUT-DTI, MEASURED.
  • The triphysics "0.15–0.28" band has no derivation in the repo. Its run card's only target is a footprint-reach envelope of 0.15–0.17 (fraction of the footprint within 3 px), which is not truth coverage. Projection withdrawn.
  • The distal2 fleet regression (0.1497) has leave-one-site-out R² = 0.21 on 93 USER-REPORTED points. That is too weak to support a leaderboard claim.
  • Context: the public leaderboard, fetched today, shows #1 = 0.4544, #2 = 0.3916, #22 = 0.3261, and #48 = 0.2895 — so 0.2778 sits below the top 48 (leaderboard). Beating 0.2778 would not reach the top; the gap to #1 is 0.18.

6. Official rules checked (verified 2026-10-28)

  • Metric & format: distance-weighted Tversky, α = 0.2, β = 0.8, R = 300 m; submission is float32, single band, EPSG:32611, 100 m; values in [0, 1]; "data outside the bounds is null or nan." (problem page)
  • Scored truth: the public and private test sets are new faults not in the USGS database; the final round re-scores on an expanded label set. (problem page)
  • Known faults masked: see §4 item 2 (community reply).
  • NaN vs zero outside: the official text permits NaN outside bounds. This repo's stricter all-finite gate rejects NaN, so the zero-outside file is the safer of the two for any future decision. Both pass the official range rule.
